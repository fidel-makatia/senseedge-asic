# Dataset replay on the Zybo Z7-10

Everything needed to measure SenseEdge Rev. B on public vibration datasets without a sensor or
a motor: the dataset becomes 12-bit MCP3201 codes, the board's emulator plays them into the
chip exactly as the ADC would, and every window the chip decides is checked bit for bit
against the Python reference chain while the accuracy is being measured.

```
host/
  prepare_records.py     dataset -> replay records (.npz): 64-sample windows of ADC codes, labels, split
  se_link.py             the UART protocol client (sw/senseedge_zybo.c, host mode); --mock for tests
  replay.py              the measurement: all test windows through the board, bit-exact check, metrics
  evaluate.py            metrics (window/balanced/sequence accuracy, bootstrap CI, confusion, per condition)
                         and the host-model run that predicts what the board must reproduce
  weight_update.py       register-map model update test (two weight sets, decisions and alarm checked)
  divider_check.py       same windows at D = 249, 9, 4: identical results, time per window
  test_protocol_mock.py  protocol test against sw/mock (no board)
  records/               the .npz records (regenerated by prepare_records.py; not committed)
../sim/run_replay_check.py   the same replay in Icarus through the wrapper RTL (before any board)
../../../ml/train_on_records.py   trains the 8-16-4 INT8 weights on the records, exports .npz/.hex/.h
```

## Datasets

| | MaFaulDa (UFRJ) | CWRU bearing data |
|---|---|---|
| Source | http://www02.smt.ufrj.br/~offshore/mfs/ (per-class zip archives, 12.9 GB) | https://engineering.case.edu/bearingdatacenter (`<n>.mat`) |
| Rig | SpectraQuest MFS: motor, rotor, two bearings; 700-3600 rpm | 2 hp motor, drive-end bearing with EDM faults; 0-3 hp load |
| Content used | 1951 sequences x 5 s at 50 kHz; channel 2 = underhang bearing accelerometer, radial | 40 files: normal 97-100 (48 kHz), 12 kHz drive-end IR/B/OR at 0.007/0.014/0.021 in |
| Chip classes | HEALTHY = normal; BEARING_WEAR = underhang + overhang (cage, outer race, ball); IMBALANCE = 6-35 g; MISALIGNMENT = horizontal 0.5-2.0 mm + vertical 0.51-1.9 mm | NORMAL, INNER_RACE, BALL, OUTER_RACE (the chip's four outputs relabelled) |
| Split | by sequence, stratified by class and condition, 30 % test, seed 0 | unseen load: 3 hp held out (10 files), 0-2 hp train |
| Why | the only public set with the chip's own four conditions on one rig | the benchmark everyone reports; its pitfalls are known (Smith & Randall 2015) |

Fetch: `~/datasets/mafaulda/fetch2.sh` (resumable curl of the six class archives, then
`unzip` each into `~/datasets/mafaulda/extracted/`) and `~/datasets/cwru/fetch.sh` (the 40
files). Neither dataset is redistributed here.

## Pipeline

```sh
# 1. records (one global gain from the HEALTHY class; mean removed; exact rational resampling)
python3 prepare_records.py mafaulda --root ~/datasets/mafaulda/extracted --out records/mafaulda_d249.npz --gain-target 512
python3 prepare_records.py cwru     --root ~/datasets/cwru/raw           --out records/cwru_d249_g512.npz --gain-target 512
#    other sample rates: --div 142 (4.0 kS/s), --div 70 (8.0 kS/s); --policy tracked (f_s = 32 f_rot)
#    gain target 512 (a quarter of half scale) is the rule used for every result below: at 8 kS/s the
#    default 1024 clipped 20 % of the inner-race samples for the same accuracy
# 2. the model is bit-exact to the RTL (proved on 1024 random/tone/corner windows and 1024 dataset windows)
python3 ../../../verilog/dv/audit/check_fft_model.py --records records/cwru_d249.npz
# 3. weights on the integer grid of nn_engine.v; test-split metrics are what the board must reproduce
python3 ../../../ml/train_on_records.py --records records/mafaulda_d249.npz --name mafaulda_d249 --seeds 16
# 4. the whole replay in simulation through the wrapper RTL: bins, features, class, confidence, alarm
python3 ../sim/run_replay_check.py --records records/mafaulda_d249.npz --weights ../../../ml/records/mafaulda_d249_weights.npz --n 256
# 5. the protocol against the mock firmware
python3 test_protocol_mock.py
# 6. on the board (Vitis: build sw/senseedge_zybo.c, terminal closed, SW0 down)
python3 replay.py --records records/mafaulda_d249.npz --weights ../../../ml/records/mafaulda_d249_weights.npz \
                  --port /dev/cu.usbserial-XXXX --out results/mafaulda_fpga
python3 divider_check.py --records records/cwru_d249.npz --weights ../../../ml/records/cwru_d249_g512_weights.npz --port ...
python3 weight_update.py --records records/mafaulda_d249.npz --weights ../../../ml/records/mafaulda_d249_weights.npz --port ...
```

Replay speed: a block of 64 windows is 8 KB over the UART; at 115200 baud about 0.9 s per block
including the run at D = 9 (1.1 ms per window). The MaFaulDa test split (about 100 k windows)
takes about 25 minutes; CWRU (3.6 k windows) about one minute. Compile the program with
`-DSE_BAUD=921600` and pass `--baud 921600` for an 8x faster transfer.

## What the board run measures (and what the paper quotes)

| Measurement | Script | Paper slot |
|---|---|---|
| Bit-exactness of the hardware on recorded vibration: features and decision of every window, bins of every 20th block, alarm of every window, against the reference chain | `replay.py` | Table VI last row; IX-D |
| Accuracy on MaFaulDa (window, balanced, sequence-majority, 95 % CI by sequence bootstrap, confusion matrix, per condition: severity and speed) with the on-chip network | `replay.py`, `evaluate.py` | VIII (dataset protocol), Table VII "Accuracy" |
| Accuracy on CWRU, unseen load, at three sample rates (D = 249, 142, 70) | `replay.py` with the three record files and weight sets | VIII sample-rate policy |
| Register-map model update: same windows, two weight sets, decisions and alarm as predicted | `weight_update.py` | VIII-D, IX-D |
| Divider independence and replay time per window | `divider_check.py` | IX-C |
| Weight read-back (53 words) on every block reset | inside `replay.py` | IX-B |

The host-model numbers (`ml/records/<name>_train.md`) are the expected values: the model is
proved bit-exact to the RTL and the RTL to the SKY130-mapped netlist, so a board run that
differs from them is a defect, not a measurement.

## Host-model results so far (what the board must reproduce)

CWRU, four classes, 3-hp load held out (10 files, 3.6 k to 12.8 k windows), best of 16 seeds,
gain target 512, window accuracy with the 95 % sequence-bootstrap interval:

| records | f_s | window | balanced | sequence majority | recall N / IR / B / OR |
|---|---|---|---|---|---|
| `cwru_d249_g512` | 2.29 kS/s (D=249, the reset value) | 75.9 % (57.5-88.4) | 77.7 % | 90 % | 86.9 / 53.7 / 80.4 / 89.9 |
| `cwru_d142_g512` | 4.0 kS/s (D=142) | 65.1 % (47.0-80.7) | 60.9 % | 80 % | 40.2 / 55.8 / 74.2 / 73.5 |
| `cwru_d70_g512` | 8.0 kS/s (D=70) | 80.5 % (72.3-88.1) | 83.7 % | 100 % | 99.4 / 79.2 / 83.1 / 73.1 |

The intervals are wide because the unit is the held-out file (ten of them); the three rates are
three values of one register. MaFaulDa rows follow when its archives are in.
